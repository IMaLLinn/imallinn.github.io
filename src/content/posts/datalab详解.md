Data Lab 给了一组留空的 C 函数。整数题要在规定的运算符和常量限制下完成，浮点题则要用整数位模式表示 IEEE 754 单精度的运算结果。做这类题时，我先把输入写成二进制，画出最后要留下的位，再想怎样用允许的运算把它们移到位。题设按 32 位补码和算术右移来解释，下面的有符号移位也按这个模型推。

## 掩码先画出要保留的位

| 问题 | 位上的做法 |
| --- | --- |
| `bitAnd` | 用德摩根定律把与改写为 `~(~x \| ~y)` |
| `getByte` | 右移 `n << 3`，再用 `& 0xFF` 留下一个字节 |
| `logicalShift` | 算术右移后，清掉高位补出的符号位 |
| `fitsBits` | 左移 `32 - n` 再算术右移，检查能否回到原值 |
| `ilog2` | 用 16、8、4、2、1 位逐段查找最高位的 1 |

取字节最好对照一个能看清位置的数。把 `0x12345678` 的字节按从低到高编号，取编号 1 就是取 `0x56`。先右移 8 位，值变成 `0x00123456`，再与 `0xFF`，其余字节就都被清掉。输入换成负数时，算术右移补出来的 1 在更高位，最后也会被这个掩码清掉。

做 `logicalShift` 时没法固定切掉 24 位，右移几位就只能清最高的几位。我在笔记里曾直接把最高位算术右移再取反，少算了最高位本来就有一个 1。以右移一次为例，`0x80000000 >> 1` 会得到最高两位都是 1 的 `0xC0000000`，直接取反会清掉两位。实现里先左移一位才取反，掩码写成 `~(((1 << 31) >> n) << 1)`。用 `0x80000000` 对照几个边界，右移 0 位应保留原值，右移 1 位应得到 `0x40000000`，右移 31 位应只剩 1。

## 每两位先数一次

到了 `bitCount`，目标从「取某一段」变成了「数出所有的 1」。整数题不能用循环，先把每对相邻位的计数存回那两位，再合并计数。以低四位 `1011` 为例，`10` 有一个 1，`11` 有两个 1。第一轮把四位改写成 `0110`，表示两组计数分别为 1 和 2，再相加就得到 3。

`0x55` 的二进制是交错的 `01010101`。一个掩码取每组较低位，输入先右移再掩码，就取到每组较高位，两份相加得到各组的数。下一轮用 `0x33` 选两位宽的计数，再往后用更宽的组。检查这段时，用 0、只有最高位为 1、以及全 1 三个值就能分别对照出 0、1、32。

```c
int bitCount(int x) {
    int m1 = 0x55 | (0x55 << 8);
    int m2 = 0x33 | (0x33 << 8);
    int m4 = 0x0F | (0x0F << 8);
    int m8 = 0xFF | (0xFF << 16);
    int m16 = 0xFF | (0xFF << 8);

    m1 = m1 | (m1 << 16);
    m2 = m2 | (m2 << 16);
    m4 = m4 | (m4 << 16);

    x = (x & m1) + ((x >> 1) & m1);
    x = (x & m2) + ((x >> 2) & m2);
    x = (x + (x >> 4)) & m4;
    x = (x + (x >> 8)) & m8;
    return (x + (x >> 16)) & m16;
}
```

## 补码的边界比正数样例有用

同样是右移，到了 `divpwr2` 就有舍入的坑。算术右移会让 `-3 >> 1` 得到 −2，题目要的是向零截断的 −1。负数要先加偏移量 $2^n-1$，例如先把 −3 加 1 再右移。另拿同样是负数、但恰好整除的 −4 对照，加上 1 成为 −3，右移仍得到 −2。偏移量把有余数的负数推回正确的区间，又没把整除样例推到下一档。

代码不写分支。用 `x >> 31` 得到全 0 或全 1，再与偏移量做与，正数和零就自然加 0。类似的办法也用在 `fitsBits`。比如判断一个数能不能塞进四位补码，先左移把原数的第 4 位送到符号位，再算术右移回来。−8 能恢复原值，把 8 送进同样的流程却会得到 −8，说明原来的正号没法用四位留下。

`bang` 用补码取负 `~x + 1`。除了零，`x` 和它的补码取负结果至少有一个最高位为 1。最小补码整数在题设的位模式里取负后仍是自己，最高位也仍为 1。判断正数则还要排除零。比较 `x <= y` 时，异号先看符号，同号再看 `y - x` 的符号，免得异号相减溢出后把正负判反。

## 单精度真正容易错在舍入

浮点题可以写分支和循环，不过函数输入输出里的 `unsigned` 仍是一串位。拿整数转单精度来说，我先拆出符号，再找绝对值的最高位 $k$，阶码是 $k+127$。最高位是规格化数隐含的 1，尾数字段取它右侧的 23 位。能装下就左对齐并补零。装不下时，先分开保留部分和舍弃部分，再看丢掉的值是否达到半个单位。超过一半就进位，正好一半时只有保留部分是奇数才进位。尾数全是 1 再进位时，隐含的 1 进到了更高一位，阶码也要跟着加一。

```c
unsigned float_i2f(int x) {
    if (x == 0) return 0;
    unsigned sign = (unsigned)x & 0x80000000u;
    unsigned value = sign ? ~(unsigned)x + 1u : (unsigned)x;
    int msb = 31;
    while ((value & (1u << msb)) == 0) msb--;

    unsigned exp = msb + 127;
    unsigned frac;
    if (msb <= 23) {
        frac = (value << (23 - msb)) & 0x7FFFFFu;
    } else {
        int shift = msb - 23;
        frac = (value >> shift) & 0x7FFFFFu;
        unsigned lost = value & ((1u << shift) - 1);
        unsigned half = 1u << (shift - 1);
        if (lost > half || (lost == half && (frac & 1))) {
            frac++;
            if (frac >> 23) {
                exp++;
                frac &= 0x7FFFFFu;
            }
        }
    }
    return sign | (exp << 23) | frac;
}
```

取绝对值前先转成无符号，最小的 `int` 也不用在有符号范围里求反。舍入规则可以拿 16,777,217 检查，它正好夹在单精度可表示的 16,777,216 和 16,777,218 中间，应选保留位为偶数的 16,777,216。再拿 16,777,219 看另一侧的情况。它夹在 16,777,218 和 16,777,220 中间，这次应当向上选 16,777,220。这对输入能区分「正好一半总是向上」和按保留位取偶。

单精度的另两题也沿用这三个字段。取负时先判断是不是 NaN，按题意原样返回，其余数才翻符号位。乘二先看阶码，非规格化数左移尾数，第一位移进阶码时自然跨到最小的规格化区间。规格化数加阶码，到全 1 时得清零尾数才能表示无穷大。输入原本已经是 NaN 或无穷大，位模式保持原样。把这些分支放在同一张纸上推一遍，最容易漏的两个交界就很明显，一个是非规格化转规格化，一个是有限值溢出到无穷大。
