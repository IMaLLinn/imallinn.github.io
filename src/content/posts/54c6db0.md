上一篇分清了变量和对象。这次从一行 `Animal pet = new Cat()` 往下看。引用声明为 `Animal`，对象却是 `Cat`。编译器会放行哪个方法？程序跑起来又会执行哪一版？

## 编译看引用，重写看对象

我把这个问题缩成两个类，各自实现一个 `speak()`。编译器按引用类型 `Animal` 检查有没有这个方法，实际进入哪个实现，要等运行时看对象。

```java
class Main {
    static class Animal {
        void speak() {
            System.out.println("animal");
        }
    }

    static class Cat extends Animal {
        @Override
        void speak() {
            System.out.println("meow");
        }
    }

    public static void main(String[] args) {
        Animal pet = new Cat();
        pet.speak(); // meow
    }
}
```

运行打印的是 `meow`。如果加一个只在 `Cat` 上声明的方法，用 `pet` 直接调会编译失败，要先用 `instanceof` 检查，再把引用转成 `Cat`。静态方法和字段也容易混，它们按类型解析，子类同名静态方法会隐藏父类方法。

还有一处会卡在编译阶段。父类只有有参构造器时，子类不能靠默认调用完成初始化，得在构造链里显式调用可用的 `super(...)`。同一个类的构造器之间则用 `this(...)` 委托。

## 同一个学号，什么时候算重复

如果把两个学号一样的学生对象放进 `HashSet`，它需要按照学号认出它们是同一个学生。要让这条规则生效，`equals()` 和 `hashCode()` 都得按同一份学号实现。若后续操作是拿学号查学生，用学号当 `Map` 的键更直接。同一键再次写入会覆盖旧值。

| 要做的事 | 常用类型 | 容易漏的细节 |
| --- | --- | --- |
| 按下标取，允许重复 | `ArrayList` | 中间插删可能要搬元素 |
| 去重 | `HashSet` / `LinkedHashSet` | 要保留插入顺序时用后者 |
| 按键查找 | `HashMap` | 迭代顺序没有保证 |
| 按键排序 | `TreeMap` | 顺序由键的比较规则决定 |

## 异常在签名里怎么看

写调用方时看签名上的 `throws`。遇到 `IOException` 这类受检异常，要么用 `catch` 处理，要么继续向上声明。`throw` 则是代码执行到某一行时主动抛出异常对象。`NullPointerException` 属于运行时异常，编译器不会强制声明。
