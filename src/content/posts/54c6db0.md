上一篇分清了变量和对象。这次从一行 `Animal pet = new Cat()` 往下看。引用声明为 `Animal`，对象却是 `Cat`。编译器会放行哪个方法？程序跑起来又会执行哪一版？

## 编译看引用，重写看对象

我把这个问题缩成两个类，各自实现一个 `speak()`。编译器按引用类型 `Animal` 检查有没有这个方法，实际进入哪个实现，要等运行时看对象。

```java
class Main {
    static class Animal {
        void speak() {
            System.out.println("animal");
        }
    }

    static class Cat extends Animal {
        @Override
        void speak() {
            System.out.println("meow");
        }
    }

    public static void main(String[] args) {
        Animal pet = new Cat();
        pet.speak(); // meow
    }
}
```

这段运行打印的是 `meow`。如果加一个只在 `Cat` 上声明的方法，用 `pet` 直接调会在编译阶段失败。确实要用这个方法时，先用 `instanceof` 检查对象类型，再把引用转成 `Cat`。静态方法和字段也按类型解析，子类同名静态方法会隐藏父类方法。看见两个类都有同名的成员时，先确认自己调用的是被重写的实例方法，才套用运行时按对象选择的规则。

构造器也适合沿调用看。父类只有有参构造器时，子类不能靠默认调用完成初始化，得在构造链里显式调用可用的 `super(...)`。如果子类为不同入参写了两套构造器，可以用 `this(...)` 把公共初始化交给同类的另一个构造器，由它继续调用父类。

## 同一个学号，什么时候算重复

接下来换一个会在集合里碰到的例子。手头有两条学生记录，来自两个不同对象，但学号一样。希望根据学号去重，就得让 `HashSet` 能认出这两条记录应当算在一起。先让 `equals()` 按学号判相等，再让 `hashCode()` 也取同一个字段。只写相等方法却没同步哈希值，集合查询就可能走不到需要比较的那一项。

```java
import java.util.HashSet;
import java.util.Set;

class Main {
    static final class Student {
        private final String id;

        Student(String id) {
            this.id = id;
        }

        @Override
        public boolean equals(Object other) {
            if (this == other) return true;
            if (!(other instanceof Student)) return false;
            return id.equals(((Student) other).id);
        }

        @Override
        public int hashCode() {
            return id.hashCode();
        }
    }

    public static void main(String[] args) {
        Set<Student> students = new HashSet<>();
        System.out.println(students.add(new Student("001")));
        System.out.println(students.add(new Student("001")));
        System.out.println(students.size());
    }
}
```

把这段单独放进 `Main.java` 运行，会依次打印 `true`、`false` 和 `1`。第二个对象没能增加元素数，因为去重用的学号相同。若后续操作主要是拿学号查信息，可以直接用学号当 `Map` 的键。同一个键写入两次时，后面的值会覆盖前面的值。先决定需要保留哪些重复、怎样找到元素，再往下选结构。

| 要做的事 | 常用类型 | 容易漏的细节 |
| --- | --- | --- |
| 按下标取，允许重复 | `ArrayList` | 中间插删可能要搬元素 |
| 去重 | `HashSet` / `LinkedHashSet` | 要保留插入顺序时用后者 |
| 按键查找 | `HashMap` | 迭代顺序没有保证 |
| 按键排序 | `TreeMap` | 顺序由键的比较规则决定 |

## 异常在签名里怎么看

调用 `readFile()` 时如果签名里有 `throws IOException`，调用方要决定自己能不能处理。能在这层给出有效反馈就用 `catch`，否则继续向上声明，把决定交给知道文件用途的调用者。方法内部遇到负年龄，用 `throw new IllegalArgumentException(...)` 抛出的是某个具体的异常。签名上的 `throws` 说的是调用者可能收到什么。像 `NullPointerException` 这样的运行时异常，编译器不会强制声明。
