先自己做一个只有一条规则的输入检查。六个数从 1 开始，后一个必须是前一个的两倍。你会先看到程序接受正确的序列，再用 GDB 找出错误序列坏在第几项。这里用随文的 C 小程序，后面才回到 Bomb Lab 的六段反汇编。

准备能分别运行 `gcc --version` 和 `gdb --version` 的终端。如果在 Windows 上用 MSYS2，先按 [Data Lab 的准备步骤](/posts/datalab%E8%AF%A6%E8%A7%A3/)装好 GCC，再在相同的 UCRT64 终端执行 `pacman -S mingw-w64-ucrt-x86_64-gdb`，安装后重查 GDB 版本。

新建空文件夹，创建 `sequence.c`，把终端切到这个目录。

## 第一步 · 先跑对照组

把代码保存为 `sequence.c`。传任意一个命令行参数就会选择有错的第二组数组。

```c
#include <stdio.h>

int check_sequence(const int values[6]) {
    if (values[0] != 1) return 0;
    for (int i = 1; i < 6; ++i) {
        if (values[i] != 2 * values[i - 1]) return 0;
    }
    return 1;
}

int main(int argc, char **argv) {
    (void)argv;
    int correct[] = {1, 2, 4, 8, 16, 32};
    int wrong[] = {1, 2, 4, 9, 16, 32};
    const int *values = argc > 1 ? wrong : correct;
    puts(check_sequence(values) ? "passed" : "mismatch");
    return 0;
}
```

先执行 `gcc -g -O0 sequence.c -o sequence.exe`。运行 `./sequence.exe` 应显示 `passed`，运行 `./sequence.exe wrong` 应显示 `mismatch`。`-g` 保留变量和源码位置，`-O0` 方便把调试器看到的执行顺序与源码对上。

## 第二步 · 停在检查函数里看数据

运行 `gdb ./sequence.exe`。等提示符变成 `(gdb)` 后逐条输入下面的命令。

```text
break check_sequence
run wrong
print *values@6
print values[3]
print 2 * values[2]
continue
quit
```

第一条给函数下断点，也就是让程序到函数入口时先停下。第二条启动错误样例。停下后，整组值应是 `{1, 2, 4, 9, 16, 32}`，接着打印出来的两个数字应分别是 9 和 8。你现在能指出第 4 项为什么会失败。最后 `continue` 让程序继续打印 `mismatch`。如果 GDB 提示找不到 `values`，先确认断点确实停在 `check_sequence` 里。更多调试命令见 [GDB 手册](https://sourceware.org/gdb/download/onlinedocs/gdb.html/gdb-man.html)。

## 同一种读法用在 Bomb Lab

Bomb Lab 给我一个二进制程序，输对一行才会进入下一段。入手时我先用 `objdump -d` 找当前阶段检查输入的函数和失败分支，再开 GDB 看同一段运行时的值。比较指令前先弄清两个操作数从哪里来，之后的跳转才有意义。调试时我把几种动作分开。用 `disassemble` 看函数全貌，要跟进调用就用 `si`，只关心调用之后的状态时用 `ni`。

### 先读清楚输入和跳转

Phase 1 调 `strings_not_equal` 前，`%rdi` 指向输入，`%rsi` 指向另一串字符。跟到调用位置，用 GDB 的 `x/s` 读第二个地址，就能看到用来比较的字符串。返回后的 `test %eax,%eax` 检查结果是不是零。输入刚读到的字符串后，第一段走的是相等的分支。

Phase 2 的输入变成六个整数，`read_six_numbers` 把值写到栈上的连续区域。这里我先等调用执行完，再从数组的实际起点用 `x/6wd` 看六个 4 字节整数。读循环时，可以只跟相邻两项。偏移 `-0x4` 取前一项，`add %eax,%eax` 把它翻倍，再与当前项比较。指针每轮走 4 字节，所以这是逐项检查。首项先被检查为 1，由此推出 `1 2 4 8 16 32`。看过 GDB 里的数组以后继续执行，第二段也通过了。

### 跳转表存的是地址

Phase 3 先用 `sscanf` 读出两个整数。看到 `cmp $0x1,%eax` 时，光看常量很容易读成「至少一项」。接着的 `jbe` 会让只读到 0 或 1 项也进入失败分支。再往下看，第一个数做无符号上界检查，通过后才去索引跳转表。

```asm
callq  401353 <__isoc99_sscanf>
cmp    $0x1,%eax
jbe    400fad
cmpl   $0x7,0x8(%rsp)
ja     400fad

mov    0x8(%rsp),%eax
jmpq   *0x402470(,%rax,8)

case_0:
mov    $0xcf,%eax
jmp    case_end

case_end:
cmp    %eax,0xc(%rsp)
je     400fc0
callq  <explode_bomb>
```

用 `x/8xg` 会看到八个分支地址。看 `jmpq` 那行就能解释每一格的跨度，表以第一个数为索引，每格是一个 8 字节的地址。直接把表里的值当第二个输入会读偏一层。进一个 case，看它最终给 `%eax` 装了什么，再顺到所有分支汇合的位置，确认那里比较的是第二个输入。原记录里第 0 项装入 `0xcf`，也就是 207，所以有一组输入是 `0 207`。换另一个合法索引时，必须跟着换对应的比较值。

### 递归要看返回途中做了什么

Phase 4 的 `func4` 从 `[0, 14]` 做二分。最内层命中中点时返回 0，但这个 0 会沿调用栈往回传。向左返回 $2r$，向右返回 $2r+1$，其中 $r$ 是子调用的返回值。原来的笔记一度把「命中某个中点」当成条件，可二分里的任何一个合法值最终都会命中自己的中点。差别在回程。

用 7 可以在第一步命中，中途没有回程编码。取 3 时先向左，命中后回上一层还是 0。取 11 则先向右，命中后乘二再加一，最外层得到 1。这样才知道，题目要求返回 0 时，路径上只能一路向左或直接命中。第二个输入也必须为 0，一组可推得的输入是 `7 0`。想在 GDB 里确认推导，要等最外层 `call` 完成再看 `%eax`。

### 从目标字母反过来查表

Phase 5 又回到字符串，但条件变成了先映射后比较。长度为 6 的输入会逐字符做 `c & 0xf`，再用低四位去查一份映射表，查到的字符拼起来以后才和目标比较。此时正着算适合检查一个候选值，找输入则更适合倒过来。分别用 GDB 读出目标字符串和表内容，对目标的每个字母找表下标，最后选一个低四位等于该下标的字符。

用原记录里的例子，目标的首字母是 `f`，在表里对应下标 9。`i` 的 ASCII 编码是 `0x69`，数字字符 `9` 是 `0x39`，低四位都等于 9，所以两个字符在这一位置都会映射成 `f`。后面五个位置同理。这段要验证的是映射后的字符串是否一致，输入本身可能有很多种。

### 链表要记的是原位置

Phase 6 读六个不重复的 1–6，再把每个数换成 `7 - x`，用变换后的数从原链表选节点。这里容易直接把降序的位置写进答案，漏算这一步。GDB 里按 4 字节值、4 字节编号和 8 字节 `next` 读节点，沿指针记原位置。然后按值排成降序，最后对位置做反向映射。例如降序若对应原位置 `3 4 5 2 6 1`，输入就是 `4 3 2 5 1 6`。这组数只适用于示例链表，实际节点要从手头的二进制读。

这里把「原位置」写在值旁边很省事。比如第二个节点的值大于第一个，如果希望它先出现，应该先挑位置 2，再换算成输入 5。最后在比较循环里确认程序检查的是节点的值。节点在内存里的地址、结构里保存的编号、按原链表走到它的位置，这三项看起来像同一件事，手算时要分开记。
